# Шофёр-убийца

Источник: [Постановка задачи в Notion](https://app.notion.com/p/4122971d9e9980b88422ce4b334f05b9).
В репозитории есть симулятор и классическая обратная связь для трёх семейств
траекторий. Награда Gymnasium пока всегда `0.0`.

Из корня репозитория (Python 3.12, зависимости и точные версии в
`.python_env/pyproject.toml` и `.python_env/uv.lock`):

```bash
uv sync --project .python_env --locked --inexact
uv run --project .python_env --locked python -m RL.chauffeur_demo
uv run --project .python_env --locked python -m RL.chauffeur_demo --state 2 -2 --horizon 0.12 --trace
uv run --project .python_env --locked python -m unittest discover -s tests -v
```

`--inexact` сохраняет пакеты, установленные вручную сверх lock-файла
(например, Box2D для других упражнений).

Первый запуск дважды воспроизводит эпизод из `(0, 2.3)` с `phi=psi=0`:
80 шагов, захват при `t=4`. Второй показывает остановку по времени при `t=0.12`.
Параметры `--gamma`, `--beta`, `--dt`, `--horizon`, `--phi`, `--psi`, `--seed`
можно задавать явно. `--trace` печатает всю последовательность состояний и
применённых управлений. По умолчанию окно не открывается.

```python
from RL.homicidal_chauffeur import GameConfig, HomicidalChauffeurEnv

env = HomicidalChauffeurEnv(GameConfig(gamma=0.5, beta=0.3, dt=0.05, horizon=15.0))
obs, info = env.reset(seed=42, options={"state": (1.0, 2.5)})
obs, reward, terminated, truncated, info = env.step_controls(phi=0.7, psi=-0.4)
print(info["state"], info["elapsed_time"], info["termination_reason"])
```

Состояние — относительное положение `(x, y)` на всей плоскости. Ось `+y`
направлена по скорости преследователя, углы отсчитываются по часовой стрелке.
Среда интегрирует

```text
dx/dt = -phi*y + gamma*sin(psi)
dy/dt = -1 + phi*x + gamma*cos(psi)
```

Оба управления постоянны в течение шага RK4, включая относительный угол `psi`.
`step_controls` ограничивает конечные значения `phi` до `[-1, 1]`, `psi` до
`[-pi, pi]` через clipping; NaN, бесконечности и неверная форма отклоняются.
Фактически применённые значения возвращаются в `info["phi"]`, `info["psi"]`.

Для Gymnasium предусмотрен `step([phi])`, `action_space.shape == (1,)`.
Угол убегающего вычисляет переданная в конструктор функция
`evader_policy(obs) -> psi`. По умолчанию `psi=0` — фиксированный относительный
курс, без претензии на оптимальность. Наблюдение `float32` имеет вид
`(x, y, r, x/r, y/r)`, внутреннее состояние `float64` доступно как копия
`env.state` и в `info["state"]`.

Без `options["state"]` сброс равномерно выбирает точку из `[-4,4]^2` вне круга
захвата. Границы выбора задаются `GameConfig.initial_low/initial_high`.
Явный старт может лежать за пределами квадрата; состояние должно быть конечным,
формы `(2,)` и удовлетворять `r > beta`, как в постановке.
Повторный `reset(seed=42)` воспроизводит случайный старт; `reset()` продолжает
последовательность генератора. Динамика детерминирована при заданных управлениях.
Пользовательская стратегия убегающего также должна быть детерминированной для
точного повтора; её собственное состояние и случайность среда не сбрасывает.
Для воспроизводимого `action_space.sample()` отдельно вызовите
`env.action_space.seed(42)`.

Исходы:

| Условие | terminated | truncated | info["termination_reason"] |
|---|---|---|---|
| Захват `r <= beta` | True | False | `"capture"` |
| Достигнут горизонт без захвата | False | True | `"time_limit"` |
| Эпизод продолжается / только что сброшен | False | False | `None` |

`info` также содержит расстояние, число шагов, модельное время `elapsed_time`
и длительность последнего шага `dt`. Причина сохраняется в
`env.termination_reason` до следующего сброса. После завершения нужен `reset()`.
При одновременном захвате и достижении горизонта приоритет у захвата.
Последний шаг укорачивается до горизонта, даже если он не кратен шагу времени.

Для аффинной динамики при постоянных управлениях RK4 выражается полиномом
четвёртой степени по времени. Пересечение его траектории с окружностью захвата
ищется внутри шага, включая случай входа и выхода за один шаг; время захвата
остаётся численным приближением RK4. Квадрат стартов не ограничивает движение.

## Диагностика динамики и шага

```bash
uv run --project .python_env --locked python -m unittest discover -s tests -p test_homicidal_chauffeur.py -v
uv run --project .python_env --locked python -m RL.chauffeur_diagnostics
```

Тесты сверяют координаты и знаки с точными решениями для прямой и максимального
поворота в обе стороны. Отдельно проверяются касание границы, отказ при старте
в замкнутом круге захвата, захват ровно на горизонте, остановка до захвата за
горизонтом и пересечение круга между концами шага на прямой и на вираже.

[Статический график](chauffeur_diagnostics.png) показывает четыре траектории в
относительных координатах с кругом захвата. Маркеры на линиях показывают конец
эпизода. Скрипт печатает максимальную евклидову ошибку координат относительно
точного решения в моменты, записанные симулятором.

| Контрольный случай | `dt = 0.05` | `dt = 0.025` |
|---|---:|---:|
| Прямая погоня P1 | Захват при 4 | Захват при 4 |
| Максимальный поворот без захвата | Ошибка координат 8.08e-8 | Ошибка координат 5.08e-9 |
| Максимальный поворот с захватом | Захват при 1.048481558 | Захват при 1.048481508 |
| Почти касательный поворот | Ложный захват при 1.570746050 | Горизонт 2.3 без захвата |

При почти касательном повороте из `(0.5, 0.800000001)` с `phi=1, psi=0`
точное решение описывает окружность с центром `(0.5, 0)` и радиусом
`0.800000001`. Минимальное расстояние до начала координат равно
`0.300000001`, поэтому захвата нет. При `dt = 0.0125` исход тоже совпадает
с точным решением. Проверка события находит пересечение численной траектории
RK4, поэтому ошибка интегрирования может изменить исход вблизи касания.

## Классические стратегии

В [`chauffeur_classical.py`](chauffeur_classical.py) функции
`classical_pursuer(state, config)` и `classical_evader(state, config)` возвращают
кривизну `phi` и относительный курс `psi` соответственно. Аргумент `state` —
пара `(x, y)` в координатах шофёра. Для симуляции передавайте координаты из
`env.state` или `info["state"]` с точностью `float64`. `classical_feedback`
также возвращает имя ветви и непрерывное время до захвата. Эталон рассчитан на
`gamma = 0.5, beta = 0.3`. Другие значения этих параметров вызывают `ValueError`.
Знаки, ветви и контрольные старты взяты из [описания стратегий, §5](https://app.notion.com/p/4122971d9e99801991fef28883d7db17).

| Ветвь | Область в восстановленных координатах | Управления справа |
|---|---|---|
| Прямая погоня (UL) | `abs(x) <= 1e-9`, `y > beta` | `(0, 0)` |
| Поворот к UL | Время до оси `0 < a <= 0.55`, ордината выхода `2.2 <= y1 <= 2.4` | `(1, a)` |
| Первичная дуга | `y >= 0.26`, время до захвата `0 < tau <= 0.1`, терминальный угол `0.2 <= theta <= 0.5` | `(1, theta + tau)` |

При отражении `x → -x` оба управления меняют знак. Ограничения ветвей
гарантируют курс в `[-pi, pi)`. Инверсия проверяет евклидов остаток до `1e-8`, а на
границах восстановленных параметров предусмотрен допуск `1e-10`. Обе функции
управления возвращают `None` при захвате и вне поддерживаемых ветвей.
`classical_feedback` различает эти случаи по `branch == "capture"` и `None`.

```python
from RL.chauffeur_classical import classical_evader, classical_pursuer, rollout_classical
from RL.homicidal_chauffeur import GameConfig

config = GameConfig(gamma=0.5, beta=0.3, dt=0.025, horizon=15.0)
start = (1.105240, 2.278470)
print(classical_pursuer(start, config), classical_evader(start, config))
result = rollout_classical(start, config)
print(result.outcome, result.trajectory[-1].time)
```

Для смешанных прогонов `rollout_classical` принимает замену одной стороны через
`pursuer=` или `evader=` с сигнатурой `(state, config) -> float | None`.
В поворотной полосе драйвер включает `stop_at_positive_axis` в `step_controls`.
Среда останавливает шаг на первом пересечении `x=0, y>beta` вдоль полинома RK4,
выставляет `x=0` и отмечает событие в `info["axis_crossing"]`. Следующий шаг
начинается с пересчёта обоих управлений. Драйвер проверяет покрытие в каждом
состоянии выбора управления и завершает прогон с `unsupported` при выходе за
пределы ветвей. `time_limit` означает достижение заданного горизонта.

### Контрольные прогоны при горизонте 15

| Измерение | `dt = 0.05` | `dt = 0.025` | Непрерывная модель |
|---|---:|---:|---:|
| Захват на прямой из `(0, 2.3)` | 4.000000 | 4.000000 | 4.0 |
| Переключение по состоянию из `(±1.105240, 2.278470)` | 0.502863 | 0.501435 | 0.5 |
| Ордината при переключении | 2.298466 | 2.299257 | 2.3 |
| Захват после поворота с переключением по состоянию | 4.499794 | 4.499949 | 4.5 |
| Захват на первичной дуге с `theta = 0.35, tau = 0.05` | 0.049978 | 0.049994 | 0.05 |

Результаты для левого и правого поворотов совпадают. Отдельный прогон с заранее
заданным переходом в `t = 0.5` даёт времена захвата `4.499922` и `4.499981`.
Из `(0.3, 0.01)` при `phi = psi = 0` среда регистрирует касание как захват при
`t = 0.02`. У Мерца захват требует входа внутрь круга, поэтому тест касания
проверяет соглашение симулятора. [Мерц, §§2.1–2.3 и гл. III](https://sector3.imm.uran.ru/magistr/literat/MerzThesis.pdf)

### Теоретический барьер и покрытие

В [`chauffeur_theory.py`](chauffeur_theory.py) сохранена параметризация правой
и левой ветвей открытого касательного барьера для непрерывной игры. Правая
ветвь идёт от касания под углом `acos(0.5)` до `B ≈ (3.053992, -1.763223)`.
Кривые заданы независимо от шага, горизонта и эмпирических исходов. Формула
описывает геометрию барьера. Действия на самом барьере зависят от ветви игры.
[Мерц, §§2.3–2.5 и гл. III](https://sector3.imm.uran.ru/magistr/literat/MerzThesis.pdf)

Проверенное покрытие ограничено тремя ветвями таблицы. За его пределами
остаются задняя область, отворот, EL, PDL, стыки барьера и реперы P2–P8.
Удержание относительного курса в течение шага может вывести траекторию за
границу частичного эталона даже при игре классической пары. Например, из
граничных точек `a = 0.55, y1 = 2.2` и `theta = 0.5, tau = 0.1` прогон с
`dt = 0.025` выходит из покрытия после первого шага. Сравнение на всей сетке
стартов требует расширения и проверки области действия стратегий.
