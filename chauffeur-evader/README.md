# Шофёр-убийца

Источник: [Постановка задачи в Notion](https://app.notion.com/p/4122971d9e9980b88422ce4b334f05b9).
В репозитории есть симулятор, классические стратегии для параметров курсовой и [среда для PPO](#среда-для-ppo).
Команды для повторов и сравнений PPO: [эксперименты задачи 10](docs/chauffeur-task10.md).

Из корня репозитория с `PYTHONPATH=chauffeur-evader` (Python 3.12, зависимости и точные версии в
`.python_env/pyproject.toml` и `.python_env/uv.lock`):

```bash
uv sync --project .python_env --locked --inexact
PYTHONPATH=chauffeur-evader uv run --project .python_env --locked python -m chauffeur_evader.chauffeur_demo
PYTHONPATH=chauffeur-evader uv run --project .python_env --locked python -m chauffeur_evader.chauffeur_demo --state 2 -2 --horizon 0.12 --trace
PYTHONPATH=chauffeur-evader uv run --project .python_env --locked python -m unittest discover -s chauffeur-evader/tests -v
```

`--inexact` сохраняет пакеты, установленные вручную сверх lock-файла
(например, Box2D для других упражнений).

Первый запуск дважды воспроизводит эпизод из `(0, 2.3)` с `phi=psi=0`:
80 шагов, захват при `t=4`. Второй показывает остановку по времени при `t=0.12`.
Параметры `--gamma`, `--beta`, `--dt`, `--horizon`, `--phi`, `--psi`, `--seed`
можно задавать явно. `--trace` печатает всю последовательность состояний и
применённых управлений. По умолчанию окно не открывается.

```python
from chauffeur_evader.homicidal_chauffeur import GameConfig, HomicidalChauffeurEnv

env = HomicidalChauffeurEnv(GameConfig(gamma=0.5, beta=0.3, dt=0.05, horizon=20.0))
obs, info = env.reset(seed=42, options={"state": (1.0, 2.5)})
obs, reward, terminated, truncated, info = env.step_controls(phi=0.7, psi=-0.4)
print(info["state"], info["elapsed_time"], info["termination_reason"])
```

Состояние — относительное положение `(x, y)` на всей плоскости. Ось `+y`
направлена по скорости преследователя, углы отсчитываются по часовой стрелке.
Среда интегрирует

```text
dx/dt = -phi*y + gamma*sin(psi)
dy/dt = -1 + phi*x + gamma*cos(psi)
```

Оба управления постоянны в течение шага RK4, включая относительный угол `psi`.
`step_controls` ограничивает конечные значения `phi` до `[-1, 1]`, `psi` до
`[-pi, pi]` через clipping; NaN, бесконечности и неверная форма отклоняются.
Фактически применённые значения возвращаются в `info["phi"]`, `info["psi"]`.

Для Gymnasium предусмотрен `step([phi])`, `action_space.shape == (1,)`.
Угол убегающего вычисляет переданная в конструктор функция
`evader_policy(obs) -> psi`. По умолчанию `psi=0` — фиксированный относительный
курс, без претензии на оптимальность. Наблюдение `float32` имеет вид
`(x, y, r, x/r, y/r)`, внутреннее состояние `float64` доступно как копия
`env.state` и в `info["state"]`.

Без `options["state"]` сброс равномерно выбирает точку из `[-4,4]^2` вне круга
захвата. Границы выбора задаются `GameConfig.initial_low/initial_high`.
Явный старт может лежать за пределами квадрата; состояние должно быть конечным,
формы `(2,)` и удовлетворять `r > beta`, как в постановке.
Повторный `reset(seed=42)` воспроизводит случайный старт; `reset()` продолжает
последовательность генератора. Динамика детерминирована при заданных управлениях.
Пользовательская стратегия убегающего также должна быть детерминированной для
точного повтора; её собственное состояние и случайность среда не сбрасывает.
Для воспроизводимого `action_space.sample()` отдельно вызовите
`env.action_space.seed(42)`.

Исходы:

| Условие | terminated | truncated | info["termination_reason"] |
|---|---|---|---|
| Захват `r <= beta` | True | False | `"capture"` |
| Достигнут горизонт без захвата | False | True | `"time_limit"` |
| Эпизод продолжается / только что сброшен | False | False | `None` |

`info` также содержит расстояние, число шагов, модельное время `elapsed_time`
и длительность последнего шага `dt`. Причина сохраняется в
`env.termination_reason` до следующего сброса. После завершения нужен `reset()`.
При одновременном захвате и достижении горизонта приоритет у захвата.
Последний шаг укорачивается до горизонта, даже если он не кратен шагу времени.

Для аффинной динамики при постоянных управлениях RK4 выражается полиномом
четвёртой степени по времени. Пересечение его траектории с окружностью захвата
ищется внутри шага, включая случай входа и выхода за один шаг; время захвата
остаётся численным приближением RK4. Квадрат стартов не ограничивает движение.

Тесты сверяют координаты и знаки с точными решениями для прямой и максимального

[Статический график](chauffeur_diagnostics.png) показывает четыре траектории в
относительных координатах с кругом захвата. Маркеры на линиях показывают конец
эпизода. Скрипт печатает максимальную евклидову ошибку координат относительно
точного решения в моменты, записанные симулятором.

| Контрольный случай | `dt = 0.05` | `dt = 0.025` |
|---|---:|---:|
| Прямая погоня P1 | Захват при 4 | Захват при 4 |
| Максимальный поворот без захвата | Ошибка координат 8.08e-8 | Ошибка координат 5.08e-9 |
| Максимальный поворот с захватом | Захват при 1.048481558 | Захват при 1.048481508 |
| Почти касательный поворот | Ложный захват при 1.570746050 | Горизонт 2.3 без захвата |

При почти касательном повороте из `(0.5, 0.800000001)` с `phi=1, psi=0`
точное решение описывает окружность с центром `(0.5, 0)` и радиусом
`0.800000001`. Минимальное расстояние до начала координат равно
`0.300000001`, поэтому захвата нет. При `dt = 0.0125` исход тоже совпадает
с точным решением. Проверка события находит пересечение численной траектории
RK4, поэтому ошибка интегрирования может изменить исход вблизи касания.

## Классические стратегии

Реализация следует [отчёту в Notion, §6–§9](https://app.notion.com/p/4122971d9e99801991fef28883d7db17)
и [диссертации Мерца, гл. II–III](https://sector3.imm.uran.ru/magistr/literat/MerzThesis.pdf)
для `gamma=0.5, beta=0.3`. В `chauffeur_theory.py` строятся барьер, EL,
огибающая SE и криволинейная PDL. Геометрия не зависит от сетки стартов или
горизонта. Одна и та же обратная связь работает за пределами квадрата стартов.

`classical_feedback(state, config)` возвращает ветвь, руль `phi`, курс
`psi` и время непрерывной характеристики. На траектории безопасного касания
это время включает продолжение по Мерцу. Измеренное время до первого контакта
берётся из `rollout_classical(...).trajectory[-1].time`.

| Ветвь | Действия и следующее событие |
|---|---|
| Первичная дуга | Предельный поворот в сторону пешехода и курс по обращению дуги; вход в круг |
| Верхняя UL и выход на неё | Поворот к положительной оси; на оси оба управления равны нулю |
| Нижняя UL и выход на неё | Отворот к отрицательной оси; на оси оба управления равны нулю до стыка L |
| Отворот к EL | Предельный отворот, курс находится обращением дуги; на EL по умолчанию касательный уход к верхней UL |
| Отворот к безопасному контакту | Предельный отворот и курс по дуге касания; в открытой модели затем движение по кругу до M |
| Короткий бросок | Предельный поворот к SE; на огибающей переключение на отворот |
| Осевая и криволинейная PDL | Шофёр выбирает поворот первым; пешеход берёт курс выбранной стороны |
| Барьер | На точной линии действует правило выбранной модели захвата и приоритет стыков A, B, G, H |

`classical_pursuer(state, config)` возвращает руль, а
`classical_evader(state, config, phi)` — курс с учётом фактического руля.
Если `phi` опущен, используется выбор эталонного шофёра. Для осевой PDL
эталон при равенстве выбирает правый поворот; нулевой руль даёт правый курс.
Управления регулярных ветвей отражаются по `x → -x`. Для расчёта курса
используются координаты `float64`. При недоступном действии прогон даёт
`unsupported`; при старте в замкнутом круге — захват в момент 0.

Общий шаг для классики, эвристики и PPO: определить и ограничить руль, передать
его пешеходу, затем двигаться до первого события или конца интервала `dt`.
На свободной дуге между решениями руль и курс пешехода в неподвижной системе постоянны.
Поэтому относительный курс изменяется как `dpsi/dt = -phi`, и дуга
интегрируется по точной формуле. Это сохраняет касательные характеристики
Мерца, которые могут потеряться при удержании относительного угла. Прямые
вызовы `step_controls(phi, psi)` для контрольных опытов по механике по-прежнему
используют RK4 с постоянными относительными управлениями.

На оси и особых линиях шаг может закончиться раньше `dt`. Следующее решение
получают оба игрока; для PPO это новый вызов политики. В траектории отмечены
время, пришедшее состояние, фактически применённые управления и событие.
В смешанном прогоне можно заменить шофёра функцией `(state, config) -> phi`
или пешехода функцией `(state, config, phi) -> psi`.

Диагностические прогоны:

```python
from chauffeur_evader.chauffeur_classical import rollout_classical

reference = rollout_classical((0.45, 1.0))
opened = rollout_classical((0.29085400128, 0.92860196313), mode="merz")
expanded = rollout_classical((0.29085400128, 0.92860196313), virtual_radius=0.30025)
```

По умолчанию контакт с истинным кругом завершает эпизод, включая касание.
В режиме Мерца безопасный контакт продолжается; `virtual_radius` строит
характеристики с положительным зазором и сохраняет захват на истинном радиусе.
Скольжение на EL проверяется с `slide_el=True`, движение по огибающей с
удержанием поворота — с `follow_se=True`. Эти варианты запускаются отдельно
от общего сравнения. Тесты воспроизводят P1–P8, отражённые дуги, переходы на
EL и SE, обе стороны PDL и безопасный контакт с уменьшением зазора.

## Сравнение политик

Классический шофёр и эвристика играют против классического пешехода по общему
протоколу. При недоступном действии исход `unsupported` учитывается отдельно от
тайм-аута. Для оценки сохранённого агента добавьте `--checkpoint`: оценщик
загрузит SB3 PPO на CPU и вызовет его детерминированно в те же моменты выбора.

Обычная оценка, включая `--benchmarks`, использует пешехода с зазором
`--clearance 0.001` при истинном радиусе захвата 0.3. Это первое внешнее
приближение из [§8 правил стратегии](https://app.notion.com/p/4122971d9e99801991fef28883d7db17).
Параметр `--dt` задаёт шаг решений. Для воспроизведения опубликованных прогонов
без зазора укажите `--clearance 0 --dt 0.05`.

При одном и том же параметре барьера $s$ увеличение радиуса на δ смещает
линию на δ по нормали в медленную сторону. На защитной линии пешеход проверяет
нормальную скорость выбранного курса при фактическом руле. Если скорость
неположительна, он выбирает нормаль $p_b$. При предельном повороте к пешеходу
это ведёт вдоль барьера к точке касания виртуальной окружности. При входе
с быстрой стороны защита включается по достижении той же линии.
Если между стартом и истинным барьером или кругом недостаточно места,
берётся половина доступного зазора. При точном старте на истинном барьере
сначала применяется правило §8 для замкнутой цели. Зазор фиксируется после
появления места для защитной линии.

На безопасной дуге курс непрерывно поддерживает нулевую радиальную скорость,
а угловая скорость зависит от фактического руля. Оба игрока получают новое
решение при первом достижении виртуальной окружности и при отрыве в точке M.
При поперечном входе на передней части окружности управление пересчитывается
для истинного круга. Захват фиксируется при первом $r\leq 0.3$.

Итоговые старты заданы [постановкой задачи в Notion](https://app.notion.com/p/4122971d9e9980b88422ce4b334f05b9).

Режим `--benchmarks` проводит 24 эпизода с тем же проверенным PPO и
протоколом первого контакта. Он создаёт:

- `figures/P1.png` … `figures/P8.png` с графиками `x(t)`, `y(t)`, `y(x)`,
  `φ(t)` и `ψ(t)`. Координаты показаны в системе шофёра. На каждом
  интервале руль постоянен, а относительный курс на графике меняется по
  формуле `ψ(t) = ψ_start − φ(t − t_start)`.
- `benchmarks.csv` в формате прежнего отчёта. Строка содержит идентификатор

  руль и курс начала завершившегося интервала, а также событие. В начальной
  строке поля управления пусты.
- `benchmark_run.json` с параметрами игры и данными checkpoint, включая
  SHA-256 и seed обучения.

Чтобы подключить другого шофёра, передайте функцию
`pursuer((x, y), config) -> float | None` в ту же процедуру:

```python
from chauffeur_evader.chauffeur_evaluation import compare, evaluate_pursuer, final_grid, heuristic_pursuer

starts = final_grid()
baseline = evaluate_pursuer(heuristic_pursuer, starts)
candidate = evaluate_pursuer(my_pursuer, starts)
print(compare(candidate, baseline))
```

**Основной критерий улучшения** — положительная разница долей захвата до
`T` на фиксированной итоговой сетке. Пока исходы частично неизвестны,
улучшение на всей сетке подтверждает только положительная нижняя граница
этой разницы. Для отдельной политики с `C` захватами и `U` исходами
`unsupported` границы доли равны `[C/N, (C+U)/N]`, где `N` — число
стартов. Для разницы `кандидат − эталон` вычитаем верхнюю границу
эталона из нижней границы кандидата и наоборот. Это границы при неизвестных
исходах, а не доверительный интервал.

На стартах, где завершились оба прогона, дополнительно считаем доли захватов
и долю пар «захват / тайм-аут». На всей сетке отдельно считаем долю
расхождений статусов, включая `unsupported`. Среднее время захвата и
среднюю парную разницу времён считаем только на стартах, где поймали оба шофёра.

На сетке задачи 06 при `T=20` классическая пара дала 6 532 захвата.
Эвристика дала 6 278 захватов и 254 тайм-аута. В обоих прогонах
`unsupported = 0`. Это исходы выбранного протокола первого контакта;
они не являются доказательством выигрыша во всей плоскости.

## Среда для PPO

[Замеры CPU и MPS и границы переноса среды на GPU](docs/chauffeur-mps.md).

```python
from stable_baselines3 import PPO

from chauffeur_evader.chauffeur_ppo import ChauffeurPPOEnv

env = ChauffeurPPOEnv(clearance=0.001)
model = PPO("MlpPolicy", env, n_steps=64, batch_size=32, n_epochs=1, seed=42, device="cpu")
model.learn(total_timesteps=128)
```

Настройки в примере предназначены для проверки интеграции. Агент задаёт
`phi` в `Box(-1, 1, shape=(1,), dtype=float32)`. В примере пешеход играет с запрошенным зазором 0,001.
`ChauffeurPPOEnv(clearance=0)` и конструктор без аргументов воспроизводят
исторический режим. При отдельной оценке checkpoint укажите тот же
`--clearance` (по умолчанию у оценщика 0,001). Отсутствующее управление завершает эпизод с причиной
`unsupported`.

Наблюдение `float32` имеет вид `(f(x), f(y), f(r), x/r, y/r, (T-t)/T)`.
Здесь `f(z) = (2/pi) * atan(z/s)`, а `s` — максимум из модулей границ
стартового квадрата и `beta` (`s=4` по умолчанию).

Награда на шаге — `float(termination_reason == "capture") - info["dt"] / T`.
Без дисконтирования захват в момент `t_c` даёт `1 - t_c/T`, тайм-аут — `-1`.
Захват и дедлайн передаются PPO как `terminated=True, truncated=False`.
При дедлайне причина остаётся `time_limit`, и SB3 не прибавляет оценку
будущего возврата. При совпадении событий приоритет у захвата.
Старый чекпойнт из [задачи 08](https://app.notion.com/p/4112971d9e99818ebbc9f62448036843)
можно оценить новой командой, но для сравнения качества обучения на обновлённой
среде нужен новый запуск.

### Передача агенту 08

Команда из корня репозитория запускает новую серию `wide + potential` на seed
17, 29 и 43 с сохранением моделей после 131 072 и 262 144 решений. Один
зазор `--clearance 0.001` используется при обучении PPO и при оценке
PPO, классического и эвристического водителей.
Запрошенное значение сохраняется в `settings.json` каждого seed.

```bash
PYTHONPATH=chauffeur-evader .python_env/.venv/bin/python -m chauffeur_evader.chauffeur_task10.length \
  --architecture wide --reward potential --clearance 0.001 \
  --output chauffeur-evader/data/ppo-clearance-0001
```

При γ=0,5, β=0,3, dt=0,05 и T=20 среда и `rollout_feedback` используют одно
правило выбора радиуса на эпизод. На истинном барьере выбор откладывается
до схода с линии. Виртуальная окружность задаёт момент смены управления.
Первое касание истинной окружности завершает эпизод, в том числе внутри шага.

Проверка на checkpoint seed 43 воспроизвела на P4 при t=1 руль +0,90541768
и событие `virtual_entry` через 0,036148675. Обучение и оценка дали одинаковые
координаты, события и время на каждом решении до тайм-аута в T=20.
На старте (0; 0,31) при нулевом руле пересечение виртуальной окружности
произошло в t=0,018, захват — в t=0,020. Тесты также проверяют выбор нового
радиуса после сброса, касание на истинном барьере и обе награды до конца эпизода.

Все 63 теста проекта прошли. Короткое обучение SB3 `wide + potential`
на CPU с seed 43 выполнило 1 024 решения и завершило два эпизода по времени.
Сохранённая модель загрузилась и прошла оценку на P4 и на старте (0; 0,31).
Отдельный прогон команды серии на этих двух стартах и seed 43 создал оба
checkpoint на сокращённых бюджетах 1 024 и 2 048 решений и записал отчёт.
