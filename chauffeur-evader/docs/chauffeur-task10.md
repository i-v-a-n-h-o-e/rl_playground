# Задача 10 · Повторяемость обучения PPO

[Условия в Notion](https://app.notion.com/p/4112971d9e9981ce985be3f97211da7a) ·
[Выбор контрольной конфигурации в задаче 09](chauffeur-task09.md)

[Зафиксированные результаты и протокол следующих сравнений](chauffeur-task10-freeze.md)

Запускайте команды из корня репозитория в окружении проекта:

```sh
uv sync --project .python_env --locked --inexact
```

Все скрипты записывают артефакты в `chauffeur-evader/data/chauffeur-task10/`. Чтобы провести
новую серию, передавайте один и тот же `--output /путь/к/каталогу` всем её
скриптам. Каталог отдельного эксперимента должен быть новым.

1. Измерьте разброс базового PPO с сетями управления и оценки 32×32:

   ```sh
   PYTHONPATH=chauffeur-evader .python_env/.venv/bin/python -m chauffeur_evader.chauffeur_task10.baseline
   ```

2. Обучите PPO с сетью управления 64×64 и сетью оценки 32×32. Скрипт
   сравнит результаты с первым экспериментом попарно по seed. Рассматривайте
   широкую сеть, если прирост повторяется на нескольких seed.

   ```sh
   PYTHONPATH=chauffeur-evader .python_env/.venv/bin/python -m chauffeur_evader.chauffeur_task10.width
   ```

3. При устойчивом отставании от эвристики проверьте потенциальную добавку.
   Укажите выбранную архитектуру: `baseline` или `wide`. Скрипт обучит модель
   с новой наградой и возьмёт контроль с базовой наградой из пункта 1 или 2.

   ```sh
   PYTHONPATH=chauffeur-evader .python_env/.venv/bin/python -m chauffeur_evader.chauffeur_task10.reward --architecture baseline
   ```

   Базовая награда: `1[capture] − dt / 20`. Добавка:
   `0.99 * Phi(s_next) − Phi(s)` при `Phi(s) = 0.1 / (1 + (d(s) − 0.3) / 4)`.
   При захвате и тайм-ауте `Phi(s_next) = 0`.

4. Если есть машинное время, укажите выбранные архитектуру и награду (`base`
   или `potential`). Скрипт обучит по одной модели на seed и сохранит две
   версии её весов после обновлений на 131 072 и 262 144 решениях.

   ```sh
   PYTHONPATH=chauffeur-evader .python_env/.venv/bin/python -m chauffeur_evader.chauffeur_task10.length \
     --architecture baseline --reward base
   ```

Оценка детерминированная: одни и те же 512 стартов `tuning_starts()` (seed 42),
классический пешеход, первый контакт, захват к T = 20. Итоговая сетка не
используется. Во всех сравнениях участвуют seed **17, 29, 43**. Бюджет на
модель — 131 072 решения, если не проверяется длина обучения. CPU, один поток
PyTorch, скидка 0,99, rollout 1024, batch 64, 10 эпох, `learning_rate=3e-4`,
`gae_lambda=0.95`, `ent_coef=0`. Стартовое распределение среды не меняется.

После каждого эксперимента откройте `report.md` в его подкаталоге: `baseline`,
`width`, `reward-<архитектура>` или `length-<архитектура>-<награда>`. Там есть
захваты по каждому seed, среднее и диапазон, разница с эвристикой и (где есть)
с вариантом контроля. Новые запуски также сравнивают каждый чекпойнт с классической
стратегией. Время сравнивается только на общих захватах; ничья по числу захватов
не считается превосходством.

Рядом лежат `heuristic.csv` и `classical.csv`. Каждый `seed-*` содержит настройки и версии
(`settings.json`), логи обучения (`progress.csv`, `training.monitor.csv`,
`training.json`), модели `ppo-<решения>.zip` и результаты по каждому старту
`episodes-<решения>.csv`.
